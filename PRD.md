# PRD: Аналитика программной сетки и спроса аудитории (Казахстан)

**Статус:** Draft v1
**Дата:** 26.09.2026
**Автор/заказчик:** Программный директор телеканала (Казахстан)

---

## 1. Проблема

Программный директор принимает решения по сетке вещания в основном на интуиции и разрозненных источниках. Даже при наличии подписки на TNS/Kantar нет единого места, где рейтинги по слотам сопоставлены со спросом аудитории на жанры и происхождение контента — из-за этого сложно быстро находить недооценённые зоны роста рейтинга и дохода.

## 2. Цель продукта

Дать программному директору быстрый, итеративный инструмент для проверки гипотез по сетке — без цикла постановки задачи в IT-отдел. Формат — не классическая разработка, а серия интерактивных веб-инструментов («вайб-кодинг»), каждый из которых можно скорректировать за один разговор.

## 3. Пользователи

- **Основной:** программный директор — приоритизация контента, перестановки сетки, обоснование прайса.
- **Вторичные:** отдел рекламы/маркетинга, продюсеры, руководство (быстрые отчёты).

## 4. Задачи (Jobs to be done)

1. Увидеть сводную картину сетки: сильные/слабые слоты — без ручной сборки таблиц.
2. Сопоставить фактическую сетку со спросом аудитории (происхождение, жанр, тайминг).
3. Проверить гипотезу о перестановке до реального эфирного решения.
4. Не путать разные профили аудитории (эфир 45+ vs интернет/стриминг 18–34).

## 5. Функциональные требования (модули)

| № | Модуль | Статус | Описание |
|---|---|---|---|
| 1 | Сетка вещания и рейтинги по слотам | ⏳ Не начат | Визуальная сетка недели, рейтинг/доля по слоту, подсветка слабых/сильных. Требует внутренних данных TNS/Kantar. |
| 2 | Спрос vs предложение по происхождению контента | ✅ Готов | Бегунки «доля эфира» vs фиксированный «спрос аудитории», разрыв, сортировка по возможностям. |
| 3 | Жанровые и тайминговые ориентиры | ✅ Готов (текстовый блок) | Топ-жанры, прайм-тайм, пиковый день недели. Не интерактивно — качественные сигналы. |
| 4 | Симулятор перестановок сетки | ⏳ Не начат | Перетаскивание программ по слотам, прогноз влияния на рейтинг/доход. Зависит от Модуля 1. |
| 5 | Маркировка охвата аудитории (эфир/интернет/глобально) | 🟡 Частично | Есть текстовые оговорки в Модуле 2; нет отдельного визуального слоя. |

## 6. Источники данных

**Публичные (использованы):**
- TNS Central Asia / Kantar — фрагменты в СМИ, не полный отчёт
- Megogo, K Research Central Asia — жанры, тайминг, стриминг-аудитория
- inbusiness.kz — опрос молодёжи о происхождении контента
- Google Year in Search KZ (только 2016–2021) и глобальный топ
- Semrush Trending Websites — топ сайтов KZ

**Закрытые (нужны, но недоступны):**
- Полные еженедельные отчёты TNS/Kantar (TV Index 100 000+) по слотам конкретного канала
- Внутренняя аналитика продаж рекламы
- Google Trends KZ в реальном времени (зависит от доступности браузерного инструмента в сессии)

## 7. Нефункциональные требования

- Веб-платформа: самодостаточные HTML-артефакты, без установки, десктоп + мобильный.
- Итерация — в рамках одного разговора, без формального ТЗ для разработчиков на каждую правку.
- Реальные данные канала вводятся вручную (бегунки/поля), пока нет прямого подключения к источникам.
- Пользовательский ввод хранится локально в браузере, не передаётся на сервер.
- Язык интерфейса — русский, с возможностью адаптации под казахоязычный контент.

## 8. Ограничения и риски

- Нет прямого доступа к панели TNS/Kantar → точность зависит от того, вставит ли пользователь реальные цифры.
- Риск смешать профили аудитории (стриминг/молодёжь ≠ эфир 45+), если не маркировать источники явно.
- Публичные данные фрагментарны и устаревают (детальный TNS-срез — начало 2023, свежее почти не публикуется).
- Живые данные (Google Trends) не гарантированы каждую сессию.
- Не замена внутренней BI-системе при масштабировании (много каналов, ежедневное обновление, интеграция с биллингом).

## 9. Метрики успеха

- Программный директор использует инструмент для реального решения по сетке хотя бы раз в неделю.
- Как минимум одна гипотеза о перестановке проверена в инструменте до эфирного изменения.
- Ни одного случая, когда данные разных профилей аудитории (эфир/интернет) были перепутаны в отчёте.

## 10. Roadmap (следующие шаги)

1. Получить реальные данные сетки (хотя бы за одну неделю) → заменить демо-значения в Модуле 2.
2. Собрать Модуль 1, как только появятся данные для наполнения.
3. Добавить визуальную маркировку охвата (эфир/интернет/глобально) во все модули.
4. Собрать Модуль 4 после Модуля 1.
